# Design X 视觉、组件与交互开发规范

版本 v1.0，2026-11-18（America/Los_Angeles），源码基线 `5f9d7ee`。适用于产品界面、组件、浏览器交互和作品预览/导出的一致性。

本规范根据当前源码、已有首页/编辑器截图、[原型设计记录](design-spec.md)和[产品审计](implementation/product-readiness-audit.md)整理。保留现有视觉方向，补齐可读性、组件状态、业务交互和验收要求。本文是新增与修改的目标规范。个人海报实施批次已建立语义 token 并用于首页/创作目录；旧页面仍需分批迁移，不表示全站已经达标。

## 1. 设计方向与适用边界

- 整体为有编辑感的创作工作室：暖灰底、白色面板、深墨文字、珊瑚色强调，鼠尾草绿和米棕作有限辅助。作品摄影、排版和用户内容承担主要视觉。
- 工作区优先让用户找到任务、看清作品和完成操作。控制区保持克制，避免新增无业务意义的渐变、玻璃效果、过量阴影、装饰卡片或大面积高饱和背景。
- 首页、项目/素材库、Studio、Editor、登录及弹窗使用同一基础系统；页面信息密度可以不同，按钮、输入、状态语义保持一致。
- **产品界面与作品内容分开约束**。下文 UI 字号、颜色、间距不覆盖用户画板的设计值；作品渲染由版本化文档和共享 Renderer 决定。修改 UI 不能改变已有作品导出。
- 使用真实内容呈现状态。内置示例要标识来源，不构造虚假未读、成功进度、额度、最近时间或处理结果。能力关闭时按服务端状态呈现可执行替代路径。
- 当前基线是浅色模式；新功能不单独引入另一套主题。需要深色模式时为全套语义 token 和作品背景分别设计。

## 2. 色彩与语义 token

统一采用以下 `--dx-*` 命名。它们已在 `src/styles/tokens.css` 定义并由全局入口引入；组件不得各自再造接近色。动态作品/品牌颜色、真实图像颜色和明确记录的专题插画不受 UI 调色板限制。

### 基础与交互色

| Token | 数值 | 用途 |
| --- | --- | --- |
| `--dx-bg-page` | `#F8F8F6` | 页面背景 |
| `--dx-bg-surface` | `#FFFFFF` | 面板、卡片、表单 |
| `--dx-bg-subtle` | `#F1F2EE` | 次级区块、悬浮底色、画布外部底色 |
| `--dx-text-primary` | `#292B2E` | 标题、主要内容 |
| `--dx-text-secondary` | `#5F655E` | 正文辅助信息、字段说明 |
| `--dx-text-muted` | `#6B7068` | 元信息、placeholder；不是靠低透明度隐藏的信息 |
| `--dx-border-subtle` | `#E9E9E5` | 装饰性分隔线；不可作为辨识控件的唯一边界 |
| `--dx-border-control` | `#858A81` | 必须可辨识的输入框、checkbox 等边界 |
| `--dx-brand` | `#EF644D` | 珊瑚色品牌强调、装饰；不是任意白字背景 |
| `--dx-action` | `#BF452F` | 小字号白字主按钮、强调链接、操作图标 |
| `--dx-action-hover` | `#AA3927` | 主操作 hover、选中项文字 |
| `--dx-action-pressed` | `#923020` | 主操作按下 |
| `--dx-selection-bg` | `#FFF0EA` | 选中导航、选中分段/标签背景 |
| `--dx-focus` | `#AA3927` | 键盘焦点环；复杂背景另加白色隔离环 |
| `--dx-canvas-selection` | `#526C43` | Board 组织选择框、手柄；与内容颜色分离 |

`#EF644D` 保留现有品牌识别。白字放在该颜色上对比度约 **3.18:1**，不能作为普通字号按钮的合格组合。主操作使用同色相的深珊瑚色 `#BF452F`，白字对比度约 **5.11:1**。若装饰采用原品牌色，不承载必须阅读的小字号白字。

### 状态色

| 语义 | 前景 token / 数值 | 背景 token / 数值 | 表达要求 |
| --- | --- | --- | --- |
| 成功 | `--dx-success` / `#346447` | `--dx-success-bg` / `#EDF5EE` | 完成图标 + 明确结果 |
| 警告 | `--dx-warning` / `#8A5700` | `--dx-warning-bg` / `#FFF5DD` | 原因 + 下一步；不用于普通提示 |
| 错误/危险 | `--dx-danger` / `#B83232` | `--dx-danger-bg` / `#FFF0F0` | 错误说明/危险动作，不能只变红 |
| 信息 | `--dx-info` / `#315F8A` | `--dx-info-bg` / `#EEF4FB` | 中性说明、可恢复进度信息 |

实测上述状态前景/背景对比度均超过 5:1；`text-muted` 对白色/页面底色约 5.07/4.77:1；控件边界对这两种背景约 3.53/3.32:1。数值仅适用于表中的实色组合，图片、透明度、渐变和实际叠层必须重新测量。

统一验收普通文本至少 4.5:1；大文本（24 CSS px，或约 18.7 CSS px 且粗体）至少 3:1；辨识控件、选择与焦点的非文本视觉至少 3:1。错误、选中、运行状态不能只靠颜色区分。禁用控件仍应可辨认并有可见原因，不把关键说明一起降透明度。

## 3. 字体与排版

### 产品界面

统一字体栈为 `"Noto Sans SC Variable", "PingFang SC", "Microsoft YaHei", sans-serif`。仓库已有随包字体依赖；UI 逐步迁移到同一字体来源，不依赖某台开发机独有的 Avenir/PingFang。品牌字标作为独立视觉资产保留。

| 层级 | 字号 / 行高 | 字重 | 使用范围 |
| --- | --- | --- | --- |
| 首页主标题 | 桌面 36–44 / 1.2；小屏 28–32 / 1.3 | 600–700 | 首页一级表达，不能占用编辑器空间 |
| 页面标题 | 28 / 1.35；小屏 24 / 1.4 | 600 | 项目、素材、目录页 |
| 区块标题 | 20 / 1.4 | 600 | 列表区、配置区、弹窗标题 |
| 卡片/面板标题 | 16 / 1.5 | 500–600 | 卡片名称、属性面板分区 |
| 正文、按钮、字段标签 | 14 / 1.5；段落正文可用 16 / 1.6 | 400–500 | 主要阅读和操作 |
| 元信息、辅助标签 | 12 / 1.5 | 400–500 | 时间、格式、计数；不代替主要正文 |
| 输入内容 | 桌面至少 14；手机至少 16 / 1.5 | 400 | 避免移动端输入聚焦缩放 |

产品关键文字不得小于 12px。历史 CSS 中 7–11px 的业务标签、说明不作为继续开发的基线；作品缩略图内按比例缩小的文字不适用此限制。装饰性英文小字不承载独有信息。

中文正文不增加字距；英文眉题可用 0.08em，不用于按钮/表单。标题最多两行，项目名允许换行或省略并提供完整名称；错误、费用、保存状态不能截断。测试长中文、中英混排、长文件名、数字和空值，不依靠固定短文案撑布局。

### 作品字体

共享渲染当前使用 Noto Sans SC Variable 和 Source Serif 4 Variable，兼容映射见 [render.tsx](../packages/doc-render/src/render.tsx)。字体菜单只列可真实渲染、预览与导出一致的字体。新增字体需随版本准备对应字体文件、加载规则及样例验证；不能只在下拉框加名字。产品主题不得替换历史文档字体或颜色。

## 4. 尺寸、布局与响应式

间距采用 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64px`。相关控件间距 8px，字段间 16–20px，卡片内边距 16–24px，区块间 24–32px。避免无理由增加 13/17/29px 等近似值；作品坐标不受影响。

圆角使用控件 8px、卡片 12px、主要面板 16px、模态框 20px，胶囊仅用于标签或分段。分隔线 1px；主焦点环 2px + 2px offset。普通卡片以边框为主，悬浮/浮层使用轻阴影，例如 `0 8px 24px rgba(41,43,46,.08)`，模态 `0 16px 48px rgba(41,43,46,.16)`；不让每个嵌套容器都带阴影。

| 场景 | 默认规则 |
| --- | --- |
| 普通桌面页面 | 内容最大宽 1560px；左右留白 32–48px；导航宽 200px，宽屏可 220px |
| 中等屏幕 | 留白 24px；导航折叠为约 64–72px 图标栏并提供可读标签/提示 |
| 手机 | 留白 16px；使用可收起导航或明确入口，不把完整桌面布局整体缩小 |
| 目录/项目/素材栅格 | 卡片目标最小宽 220px；随实际容器选择列数，常见 2–5 列；空间不足用 1 列 |
| Studio | 对话区目标 320–366px，画布占剩余空间；辅助面板挤压有效画布到 480px 以下时使用覆盖抽屉 |
| Editor | 作品占主要面积；工具和属性可收起；面板开关不改变作品尺寸、选择和缩放语义 |
| 弹窗/抽屉 | 宽不超过视口减 32px，高不超过 `100dvh - 32px`；正文独立滚动，标题/动作可见 |

基础布局断点约定为 **600、850、1100、1450px**，按容器可用宽度选择布局。Studio 在窄屏切换“对话/画布”，Editor 在空间不足时切换属性抽屉；不在手机同时挤入三栏。现有 700/760 等组件断点在对应组件迁移时统一或记录保留理由，不要求仅为文档更新修改所有媒体查询。

手机使用 `100dvh` 与 safe-area；软键盘弹起时输入区和提交按钮可达。不得用全局 `overflow-x:hidden` 掩盖布局溢出。画布内部平移、表格或工具条明确设计的局部滚动除外。200% 文本/页面缩放不能遮挡关键操作。

层级约定为内容 0、画布操作覆盖层 10、固定导航/工具栏 20、下拉菜单 40、popover 50、模态遮罩 80、模态内容 81、toast 100、tooltip 110。需要全局定位的浮层通过统一 portal 管理；模态打开时关闭或禁用背景浮层，禁止以随意增加 `z-index:9999` 解决遮挡。

## 5. 组件合同与状态呈现

同语义优先复用组件及样式。共享基础组件目标目录为 `src/components/ui/`，现有通用实现分散在页面中；迁移时先确认已有实现，避免同一种按钮/弹窗出现多个互不一致版本。基础组件不包含业务请求，业务层提供状态、权限与动作。

| 组件 | 尺寸/呈现 | 必须处理的交互与状态 |
| --- | --- | --- |
| Button | 默认高 40px，水平内边距 16px；触屏命中区至少 44×44px；primary/secondary/ghost/danger 四类 | default、hover、pressed、focus-visible、disabled、loading；同一操作区只有一个最高强调动作；loading 保留宽度/动作文本并防重复提交 |
| IconButton | 图标 16/20/24px，默认 Lucide 统一约 1.75px 描边；视觉与命中区分开 | 必须有可访问名称；tooltip 可由焦点触发；手机不能只有 hover 才可发现操作；密集桌面控件允许高 32px，触屏扩至 44px |
| Field/Input/Textarea | 字段标签在输入外部；默认输入高 40px；多行从 3 行开始 | required、help、error、readOnly、disabled、loading；`aria-invalid`/`aria-describedby` 关联错误；校验失败保留值并聚焦首错；placeholder 不代替 label |
| Select/Combobox | 选中值清晰；长选项不撑破容器；菜单不越出视口 | 优先原生 select；自定义时实现键盘选择、Escape、无结果、加载/失败和焦点返回 |
| Tabs/Segmented | 选中项用背景/指示线及字重表达 | 语义、方向键与焦点配套；切换保留草稿；不用 tabs 表达按钮动作或多个独立导航层级 |
| Card/Thumbnail | 缩略图区域固定 aspect-ratio，元信息对齐；图像加载前预留面积 | hover、focus、selected、loading、empty、error；主打开按钮与收藏/更多操作为独立兄弟控件，不嵌套 button；触屏操作不藏在 hover 中 |
| Modal/Dialog | 有标题、关闭按钮、明确主次动作 | `role=dialog`、可访问名称、焦点限制/恢复、背景不可交互；Escape 按业务关闭规则；有未提交修改时先处理草稿；关闭视图不冒充取消服务端任务 |
| Drawer/Popover/Menu | 与触发器对齐，可翻转避让边缘；固定滚动边界 | 触发器声明展开状态；Escape/外部点击规则明确；关闭恢复焦点；破坏操作在菜单内明确命名 |
| Toast/InlineAlert | toast 用于短暂轻量反馈；错误/保存冲突保留在上下文 | 成功、警告、失败用正确图标和文本；异步状态用适度 `aria-live`；失败不使用统一成功勾号；关键错误不只存在于自动消失 toast |
| Badge/Status | 12px 以上，固定语义色；必要时加图标/文字 | 状态来自真实数据；“NEW”“未读”“剩余次数”有明确来源；不靠红点假装存在消息 |
| Skeleton/Progress | skeleton 与目标内容几何接近，加载失败及时退出 | 无已知进度时使用不定进度；百分比仅来自真实可测阶段；加载/空结果/错误/禁用互相区分 |
| Upload/AssetPicker | 点击与拖拽都可用；显示格式/大小/处理状态 | 文件验证、上传中、摄取中、ready、failed、取消/重试；上传完成不等于图片就绪；来源、素材 ID、版本保持一致 |
| Task/GenerationCard | 明确任务、阶段、产物、耗时/消耗信息 | 排队、运行、部分成功、成功、失败、取消请求中、已取消、待核对；仅在状态允许时提供重试/停止/下载 |
| SaveIndicator | 靠近项目名或编辑工具栏，不遮挡画布 | 未修改、待保存、保存中、已保存、失败、离线草稿、冲突；收到服务端持久化确认后才显示已保存 |

新增组件的交付说明必须列明适用状态，不用“只有成功态截图”作为组件完成证据。展示专用的空态、错误态可以使用明确标记的测试夹具；产品正常路径不得使用夹具假装真实成功。

## 6. 交互与真实业务状态

### 导航、输入与操作

- 首页、搜索、目录、最近项目、收藏进入同一功能时，能力限制和目的地一致。按钮表示动作、链接表示导航；真实项目 ID 可刷新恢复。进入详情/返回列表保留合理筛选和滚动位置。
- 表单和创作输入保留用户内容；多步切换、面板切换、上传失败、能力关闭不自动清空草稿。破坏性离开时给出保存、保留草稿或明确放弃的路径。
- 全局搜索 `Ctrl/Cmd+K`，保存 `Ctrl/Cmd+S`，撤销 `Ctrl/Cmd+Z`，重做 `Ctrl/Cmd+Shift+Z`。不抢占输入框的文字编辑快捷键。
- 首页多行需求采用 `Ctrl/Cmd+Enter` 提交；Studio 聊天式输入采用 Enter 发送、Shift+Enter 换行，并展示提示。所有提交检查 IME composition，中文候选确认不得触发发送。原生表单遵循自身提交语义。
- 危险动作明确对象与结果。可恢复删除说明回收站及恢复；不可恢复动作提供专门确认，按钮使用“删除……”等具体文本。
- 重复点击、网络重试要在界面进行中状态和服务端幂等两层处理。请求失败不能把整个组件切到假空态；失败信息含可执行下一步。

### 保存、任务与能力

- `/api/capabilities` 及真实资源权限决定入口。不可用项显示原因或不呈现；入口判断在创建项目/扣额度之前完成。状态未知时先读取，不默认可用。
- 保存成功以返回 revision 等确认数据为准；列表刷新失败不能撤销已经成功的保存。409 显示冲突并保留草稿，不静默覆盖其他版本。
- 任务进度、结果数量、费用/配额由对应服务端记录驱动。`unknown` 受理状态显示待核对，不自动重发；部分成功显示已经可用产物，不把整批伪装成全成功或全失败。
- 关闭弹窗、离开页面、停止执行是不同动作。已接收任务在后台继续时告知用户可去任务中心查看；取消请求被服务端确认后才表示已取消。
- 内置示例、上传素材、AI产物、可编辑画板有不同类型与来源。图片不因在画布上显示就变成可编辑图层；“加入可编辑画板”明确实际转换结果。

### 画布手势

- 选择、拖动、缩放、撤销由统一领域行为承载；组件开关/视口虚拟化不丢选中对象和修改。手势过程中用即时预览，结束合并成业务操作，避免每像素保存。
- 锁定、隐藏、多选、删除、分区成员移动必须有一致反馈；键盘也能选择、移动或通过属性面板完成关键调整。
- 控制手柄的命中区不随作品缩放缩小，桌面至少 24 CSS px，触屏目标 44px；手柄可见尺寸可更小，邻近命中区不得互相覆盖造成误操作。
- 应用外壳保留正常页面滚动/触控；仅画布交互区域使用必要的手势拦截，不能全局禁止触摸滚动、文字选择或浏览器缩放。

## 7. 组件渲染、作品呈现与资源

- 优先使用语义 HTML；图标仅作装饰时 `aria-hidden`，按钮仍有名称；图片有正确 alt，纯装饰图片使用空 alt。组件列表用稳定业务 ID 作 key。
- 对原始素材/作品预览默认 `contain` 并保留真实比例；编辑精选/宣传裁切可 `cover`，不得将被裁切图片冒充完整交付预览。透明图片显示棋盘背景，棋盘不写入导出内容。
- 图片声明尺寸/aspect-ratio；加载中预留位置，损坏或鉴权失败有明确占位及重试。不能静默换成示例图伪装用户作品。非首屏图片按需加载，首屏主要图像不能因无差别懒加载迟迟不可见。
- 项目缩略图优先复用 [DesignThumbnail](../src/components/DesignThumbnail.jsx) 和 [ArtboardRenderer/NodeContent](../packages/doc-render/src/render.tsx)。Board、Editor、缩略图与服务端 Renderer 共享同一文档语义，不另写一套“看起来类似”的图层布局。
- 标准模板应保存可编辑文档及版本，由该版本生成预览；首页/模板库预览与创建已共用 `template-design.js` 文档构造；编辑器内部历史配色示例和模板发布版本管理仍待迁移。模板更新不能回写用户已有作品。
- 字体加载完成、图片解码且资源可读后再截图/导出；缺字体、失效素材或尚未就绪的图片不得悄悄输出“成功”的空白文件。
- 共享渲染保持换行、字体、坐标、裁切、透明度、旋转、隐藏和层级一致。界面缩放仅改变预览，不改变文档尺寸；导出尺寸与倍率必须可核对。
- 隔离 CSS 作用域；业务页面样式不得渗透 `.dx-artboard`、Renderer 或 tldraw 内部，SDK 样式通过专门适配层修改。禁止全局改 `img/button/svg` 来解决一个局部问题。
- UI 主题 token 变化不能给作品容器施加会改变图像的滤镜、继承 opacity 或正文行高。保存状态、焦点环、选区、占位提示等编辑辅助层不得进入导出文件。
- 新增效果必须确认导出 Renderer 支持；预览可见而导出丢失的效果不能列为已支持。SVG 的 `foreignObject` 现状不能宣传为任意矢量软件通用编辑格式。

## 8. 可访问性、动画与反馈

全部关键流程支持键盘，并有持续可见的焦点。焦点不能被 sticky 工具栏或弹窗页脚遮住；`outline:none` 必须有同等可见的替代。自定义组件同时实现 ARIA 语义和真实键盘行为，不能只加属性。

非紧急异步状态使用 polite 通知；错误可用 alert，但不对每个轮询/进度跳动重复朗读。禁止仅通过 hover、颜色或动画表达必需信息。拖拽上传提供文件选择，画布操作提供属性/菜单等替代。

hover/focus 色彩反馈 120–160ms，菜单/抽屉过渡 160–220ms。以 opacity/transform 为主，避免让正文和表单随鼠标移动。遵守 `prefers-reduced-motion: reduce`，取消非必要位移动画和 skeleton 闪烁；进度文本保留。spinner 只在实际等待时出现。

对于明显耗时操作，即时响应点击并显示处理中；超过短暂等待给出阶段/任务位置。没有服务端时长依据不显示编造的倒计时或百分比。成功反馈不遮挡下一步，持续失败不依赖几秒后消失的 toast。

## 9. 开发流程与验收门槛

### 开始修改前

1. 读 AGENTS.md、本规范和相关产品审计条目；确认现有组件、接口、真实状态和环境。
2. 指定本次页面/组件、预期用户动作、必要状态、影响的断点及是否改变作品渲染。
3. 对需要视觉比较的修改保留同视口、同字体、同文档数据的修改前证据。没有旧截图时明确记录，不伪称像素对齐。

### 实施与验证

| 修改类型 | 必要验证 |
| --- | --- |
| 纯文档规范 | 链接、引用、token 一致性、色彩组合数值；不为文档跑整套业务测试 |
| 单个低影响样式修正 | 相关页面浏览器前后检查、受影响窄屏/状态；不为简单样式新增镜像实现的单测 |
| 共用 token、字体、布局、基础组件 | 首页/目录、项目/素材、Studio、Editor、认证/弹窗的代表页面与状态；键盘、对比度、长内容、缩放和跨断点检查；运行相关构建/静态检查 |
| 表单、上传、保存、任务交互 | 实际浏览器操作 + 真实 API 状态，验证刷新/失败/重复提交；按范围运行现有旅程测试 |
| 文档/字体/作品渲染 | Editor、Board/缩略图、独立 Renderer 的同份文档比较；实际文件下载；执行 `pnpm test:render` 并补充受影响样例 |

基准视口为 **1440×1000、1024×768、390×844**，窄边界再看 **320×568**；断点变化还需检查断点前后，排版变化看 200% 缩放。Safari/WebKit 或 Firefox 涉及原生输入、字体、滚动/触控差异时专项验证；未执行的浏览器不能写成已通过。

组件至少覆盖适用的默认、hover/focus、选中、禁用、加载、空、错误、成功和长内容；作品至少覆盖中文/英文、多行文字、横竖图、透明图片、旋转裁切及隐藏图层。手机覆盖导航、弹窗、输入软键盘、面板切换和关键提交，不以“无横向溢出”替代流程验收。

使用现有 `pnpm check`、`pnpm typecheck`、`pnpm build` 与 `test:e2e/test:editor/test:board/test:import/test:v2-product/test:render` 中相关项，按仓库说明配置独立测试资源。不要把默认指向本地的测试命令直接套到生产，也不并发冲击线上。原型规则检查不代表真实交互验收。

证据写入被忽略的 `tests/e2e/.artifacts/<run-id>/`，记录提交、环境、浏览器、视口、数据来源、截图、真实操作结果、已知限制及测试资源清理。截图差异逐项审阅；不得通过更新基线掩盖文字截断、操作缺失或错误状态。敏感账户、密钥及会话不写入共享报告。

交付说明写清改了什么、用户行为如何变化、验证了哪些状态、尚存何种限制。应用改动在工作区验证并提交后，使用既有流程部署 aws-1，通过正式域名复核。纯规范文档不触发服务器重新部署。

## 10. 现状差异与迁移约定

| 当前差异 | 后续规范 |
| --- | --- |
| `--accent`、`--st-coral`、`--cat-coral`、`--ed-accent`、`--ws-accent` 多个近似色 | 迁移到共享语义 token；按用途分 brand/action，不把旧 accent 直接全映射为浅珊瑚后继续配白字 |
| 正文/说明大量 8–11px，浅灰低对比度 | 修改到的组件采用第 2、3 节；其余作为分批迁移，不宣称全站已达标 |
| App 内 Modal、Workspace 内 Dialog、导入弹窗各自维护 | 迁移到共享焦点/语义/关闭机制，保留不同业务对草稿和任务的处理 |
| 每个页面有自己的按钮、阴影、圆角和媒体查询 | 共享基础组件与尺度，按真实容器宽度切换布局 |
| 统一 toast 成功勾号、静态铃铛红点、默认品牌/样例混入个人资产 | 按真实语义和来源呈现，结合产品审计修复 |
| UI 系统字体与文档打包字体来源不同；字体菜单和实际渲染映射有差异 | UI 确定字体栈，作品保留共享映射，新增字体需真实渲染验证 |
| 宣传模板预览和创建文档分开构造 | 模板版本、缩略图和可编辑文档统一来源 |

新功能及修改涉及的组件遵守本规范；旧页面按交付批次迁移，不顺带进行无关的全站重写。需要例外时在变更说明中记录具体值、原因、影响和验证，能在当前任务范围合理解决的例外由开发者处理。用户后续明确的设计要求优先，并同步维护本规范。

历史 [design-spec.md](design-spec.md) 和 [verification.md](verification.md) 保留原型来源与当时验证范围，其中演示计时、本地存储、小字号与旧上传限制不作为当前产品开发标准。
