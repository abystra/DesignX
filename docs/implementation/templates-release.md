本批将现有 8 个模板纳入不可变版本管理，保留 Editor、旧 Studio 与普通账号。工作区为 Codex，应用 `5c6b853` 已发布，见 [脱敏证据](templates-evidence-2026-11-18.json)；未启用付费 AI。

## 发布合同

`src/data/template-registry.json` 保存版本、完整可编辑文档、类别、实际尺寸、来源与 SHA-256；`releases` 选择当前公开版本或下架状态。v1 为本次归档的旧内容，v2 修正目录对画册、PPT、手册等未实现能力的描述，均为真实 600×800 单张海报。归档不代表已追溯所有历史项目。

列表、搜索、收藏预览和服务端创建共用发布版本。客户端发送 ID、版本和摘要；过期/下架返回 409，界面提示刷新后重新预览，不自动改用新版。旧 ID-only 调用兼容，服务端解析当前版本并冻结。创建事务保持权限、素材校验与幂等。项目与文档保存创建来源，后续编辑不改写；下架不删除历史记录或图片，旧作品可继续保存和导出。

内置图像采用内容摘要文件名，构建校验实际字节；服务端只接受登记的内置路径，Renderer 再核对摘要。旧路径保留，避免损坏已有作品。模板来源记录包括摄影原始 URL、许可与限制、字体包版本及随包许可，不以新发布覆盖旧证据。

版本管理在工作区完成，审核提交、测试后部署生效，无运行时公开管理接口：

```sh
corepack pnpm templates:check
node --import tsx scripts/templates.ts add /path/to/new-template-version.json
node --import tsx scripts/templates.ts publish t1 3 '明确发布原因'
node --import tsx scripts/templates.ts withdraw t1 3 '明确下架原因'
corepack pnpm templates:check --base HEAD
```

新版本号须递增；`add` 计算摘要。版本记录只增不改，旧记录/文件不删除；`publish`/`withdraw` 只改发布指针。构建检查当前 Git 基线，CI 对前一提交检查，防止修改记录后重新计算摘要冒充原版本。发布新版本前必须实际创建并导出；命令成功本身不代表线上已更新。
