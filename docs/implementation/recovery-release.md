# G1：作品异常恢复

2026-11-18（America/Los_Angeles）。承接 [剩余 Goal](remaining-goals.md) 的个人海报恢复范围，保留普通账号与既有文档 revision 合同，不引入邮件或跨设备草稿同步。

## 修复与数据合同

- 登录失效保留本机的原账号与编辑器位置，同一账号重登回到原作品；显式退出和切换账号不沿用另一账号的恢复位置。
- Editor 的 IndexedDB 草稿按账号、空间、项目、文档隔离。每次挂载拥有独立记录，双标签不再覆盖同一 key。接管旧草稿使用比较后删除，保存一个标签不能清掉另一个标签的更新；存在其他记录时提供可见恢复入口。
- 历史无归属 key 仅在服务端已授权并成功读取原项目后兼容恢复。无法访问原项目时只读取当前身份已有的归属记录，不尝试展示其他账号草稿。
- 草稿加载期间明确禁用输入；离线存储不可用时提示保留页面。保存使用最新引用，编辑期间收到旧请求确认不会清除后续修改或提前允许导航/导出。
- 项目与画板 PATCH 支持内容绑定的幂等键。Editor 在发送前将待确认请求保存在本机；丢响应后重试同一请求不会增加第二个 revision。真实并发更新仍返回冲突，读取、重放和另存副本均保留租户权限与资源存在性检查。
- 冲突可以采用最新版本或另存副本；副本创建使用持久化幂等键，进入自己的 Editor 路由，刷新后仍打开副本。原项目删除/失去访问权限时保留当前账号本机草稿，并提供明确的另存路径，服务端仍校验素材权限。
- 修复组件卸载后 ResizeObserver 访问空节点。保存错误与草稿操作沿用语义色、14px 文字和 44px 点击区。

本批没有新增数据库迁移，使用既有 `idempotency_keys` 表；无幂等键的旧客户端继续使用原 revision 行为。回退旧前端会失去新的草稿恢复界面，但不会清理新增归属记录；回退前需让用户同步重要草稿。

## 边界

- 本机草稿不是服务器备份；浏览器数据被清除后不能保证恢复，也不提供跨设备未保存草稿同步。
- 网络完全不可用时不承诺重新加载整个应用；应用已打开时保留修改，网络恢复并重新认证后继续。
- 本批处理个人海报及从旧 Studio 打开的精细 Editor。旧 Studio 的整个 Board 组织状态离线持久化仍需独立补齐，不把 Editor 的恢复证明推广为所有工作区状态。
- 真实手机软键盘、读屏和 Safari 实机仍待独立验收。生产备份、外部告警与灾难恢复继续由 G2 处理。
