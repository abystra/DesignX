# G5：首屏与真实项目缩略图

本批在 Codex 工作区实施，保持服务端分页、普通账号、Editor/旧 Studio 和共享 Renderer。发布提交、正式域名与性能数据在完成验收后填入证据，不以构建数字代替真实旅程。

## 加载与预览合同

Editor、AIStudio/Board 按进入路由动态加载。加载状态可返回作品列表，失败显示显式重新加载入口；重载保留当前路由、已保存数据和 G1 本机草稿。Studio 不再为了取得初始文档构造而静态依赖整个 Editor。首页不请求这些重模块；Studio 本身仍有大包警告，不宣称全部页面都已轻量化。

作品卡片只读取分页元信息，进入可见范围才 POST `/api/projects/:id/preview`。每个标签最多 3 个预览查询/轮询，离开可见范围停止该卡片轮询；不读取完整作品 JSON。服务端以工作区/项目锁去重，键绑定主文档 ID、revision、共享渲染源码及实际字体字节摘要，并包含 Chromium/图像处理/React 依赖版本与 Worker 渲染实现。首次任务冻结完整文档、不可变素材版本；后续状态不返回设计正文。列表来源记录移除详细许可正文，打开作品后仍可读取完整来源。

`render.thumbnail` 与用户导出分开排队，各保留 1 个 Renderer 执行位，使用同一 ArtboardRenderer 与资源/字体加载等待。产物为最长边不超过 480px 的 WebP，保存到私有对象存储，记录 SHA-256 与真实尺寸。内部预览不冒充用户导出任务，也不触发每个进度导致的全工作区刷新。

保存后的新 revision 产生新任务和文件 URL，旧图只在明确标注“旧版预览 · 正在更新”时展示；失败显示状态，可在项目卡片更多操作中“重试作品预览”。原请求、失败后的并发重试和另一端读取都不重复创建同版本任务。已排队任务的渲染指纹与当前 Worker 不同时明确失败，重新打开列表创建新版键；不让新渲染器生成结果冒充旧指纹，运维可看到对应失败原因。离线或超时不会伪报成功，也不把示例图代替作品。

图片通过认证接口 `/api/previews/:id/file` 读取，工作区 RLS、登录会话和项目未删除检查先于 ETag。响应 `private, max-age=0, must-revalidate` 并 `Vary: Cookie`，可以复用浏览器字节，但每次使用重新确认权限；跨账号、退出或删除不能凭旧 ETag 得到 304。私有文件缺失返回 410 并标记可重试；重新生成不改变作品文档。

## 生命周期与回退

迁移 `0018_project_previews.sql` 只增加索引；队列仍由既有 PostgreSQL/pg-boss 管理。GC 保持默认 dry-run，只考虑登记且超过 48 小时的对象，保护当前未删除作品当前文档版本的预览，过时版本可回收。不执行全桶清理。

缩略图是可再生派生资源，G2 数据/素材备份不额外归档这些文件；恢复后缺失预览可以明确重试生成，原始文档和素材仍以完整备份为准。运维队列报告保留预览故障类别，用户任务列表不混入内部预览。G7 业务导出指标必须只统计 `render.export`。

应用回退到 G4 可继续读取完整文档作为卡片预览，保留新增索引与已登记对象；旧 Renderer 不消费新 thumbnail 队列，回退期间这些派生任务待新版重新处理，不删除用户文档或素材。只有保留 G4 模板摘要路径支持的版本才适合回退。

## 测量方法与预算

优化前保存 G4 构建：JS 2,445,115 bytes / gzip 735,548 bytes。首屏测量以实际收到的脚本记录为准。相同 G5 API 与隔离夹具分别服务 G4/G5 构建，比较前端成本，不将后端同时变化冒充纯前端收益。

夹具：1006 份作品，最新 24 份各有 1000 图层；浏览器滚动并加载到 96 张卡；5 个并发分页读取，重复 5 组。Chrome 无头、1440×1000、回环网络，无 CPU/带宽限制。每轮新建独立数据库和 S3，基线与优化顺序运行，避免与其他浏览器或 API 测试争用计算资源。报告记录冷首页、至少 6 张首屏预览、热列表、任务/脚本/布局时间、DOM、实际完整文档请求与字节，冷生成和缓存读取分开。

本轮预算：首屏 JS gzip <220 KB；项目列表完整文档请求 0；首屏 DOM <2500；热列表本机 <8 秒；冷首次可见预览本机 <60 秒。时间预算只适用于上述环境，生产网络/更多用户/百万条数据不在承诺内。共享渲染像素门槛仍为原来的 0.5%。

## 验收进度

108 单元、111 API、类型/结构/构建已通过。新 API 覆盖 8 个同时请求去重、真实 WebP、ETag 权限、保存后旧图/新图、GC 引用保护和过期文件重试。新浏览器 6 项通过，正式构建动态加载故障、完整账户 6、海报 11、资料库 10、偏好 8、预览 6、模板 5、恢复 7、大导入 3、共享渲染 3 项通过，性能预算亦通过。渲染升级保护后新增的 4 项实际 Renderer API 回归通过，独立进程预览 6、资料库 10、渲染 3 项再次通过；对应最新代码不是仅同进程的单元验证。

| 冷首页可交互 | 957 ms | 788 ms |

新缩略图显著减少主线程与文档传输，但首次后台生成比原来的浏览器渲染慢；不把冷生成称为速度提升。已缓存作品再次打开更快，后续编辑期间可显示明确标注的旧图。请求数包含状态轮询，因此冷列表 49 次高于基线 32 次；本次优化目标是限制文档体积/DOM与保持可缓存的真实图像，不隐藏这项权衡。动态 Editor chunk 人为网络失败后，明确重新加载按钮恢复原项目，正式构建故障旅程通过。
