# B2：普通账号与账户设置

2026-11-18（America/Los_Angeles）。按用户明确要求，首版采用普通用户名与密码账号，邮件投递、邮箱验证和邮件找回不再是首版依赖。已有邮箱账号继续作为登录标识使用。

2026-11-19 更新：按用户要求，公开注册现默认关闭。下文注册验收是历史功能记录；现行入口与服务器配置见 [注册关闭记录](registration-closure.md)。已有账号登录、改密和会话管理继续保留，无邮件依赖。

## 用户任务与合同

- 注册填写用户名、昵称、密码和确认密码，直接进入个人空间。用户名 3–32 位，以英文字母开头，可用字母、数字、下划线、点和短横线，不区分大小写；密码 10–128 个字符。登录账号固定，昵称可修改。
- 登录页接受用户名或已有邮箱账号。已有用户 ID、密码哈希、会话、个人空间和作品关系保持有效；不补造邮箱、不强制迁移旧用户。
- 侧栏和头像进入账户设置，桌面、折叠侧栏与手机保留入口。昵称、空间名称提交服务端后同步界面，刷新后保留。
- 修改密码须验证当前密码，新密码及确认一致。成功后轮换当前设备 Cookie、撤销全部旧会话，当前设备继续使用。
- 可主动退出其他设备，或退出当前设备；请求失败保留页面并显示重试信息。已保存的作品在重新登录后可打开。
- 注册、资料保存和改密使用真实等待/成功/失败状态；头像首字和空间名称来自账户资料。采用共享语义色、14px 正文、12px 辅助信息、44px 点击区域与手机 16px 输入。

新增 `PATCH /api/auth/profile`、`POST /api/auth/password`、`POST /api/auth/sessions/revoke-others`。旧 `{email,password}` 注册/登录请求保留兼容；新客户端注册发送 `username`，登录发送 `account`。邮箱在兼容接口中仅作登录标识，不证明邮箱所有权。

## 持久化与会话

迁移 `0015_username_accounts.sql` 增加可空且唯一的规范化 `username`，允许新账号的 `email` 为空，同时要求至少一个登录标识。旧账号的 email 保留原值。回滚版本需保留用户名认证支持，避免新账号无法登录。

密码使用随机盐的 scrypt 哈希，数据库只保存会话令牌的 SHA-256 摘要。正式站 Cookie 为 HttpOnly / Secure / SameSite=Lax，期限 7 天。

注册的用户、空间及会话在同一事务写入。登录和改密通过用户行锁串行化；敏感写入取得锁后再次验证会话，防止并发改密复用已撤销身份。错误当前密码返回可恢复的 400，不误触发前端退出。普通 API 在下一次请求拒绝旧会话，现有 SSE 在事件读取/定时检查时结束失效连接。

公开登录与注册保持可信 IP 限流；已认证账户设置按用户计数。密码修改和设备退出各限制 10 次/15 分钟，保留 Origin 校验与租户权限。

## 范围边界
