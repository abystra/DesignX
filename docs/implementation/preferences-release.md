# G3：收藏与偏好并发

本批在 Codex 云环境开发，生产发布及脱敏旅程证据在完成部署后追加。普通账号、个人海报和分页搜索保留，未启用 AI 或邮件。

## 数据与交互合同

- 迁移 `0016_preference_revisions.sql` 为已有偏好增加 revision=1；不存在的偏好版本为 0。GET 默认保留旧 value 返回格式，响应 ETag 携带版本；`?meta=1` 返回 `{value, revision}`。
- 项目、模板、素材、目录收藏通过 PATCH `/api/preferences/:key/items` 原子增删，必须带 Idempotency-Key。不同条目的修改合并保留；同一条目的相反操作按数据库提交顺序生效。重复请求不增加版本，已完成的旧请求重放不复活后来删除的收藏。项目和素材仍验证当前租户权限。
- 品牌、参考资料和其他整体设置 PUT 必须带 If-Match；未提供版本返回 428，过期返回 409 及当前值/版本。旧客户端读取兼容，旧无条件写入明确提示刷新，不能恢复静默覆盖行为。项目收藏筛选在服务端执行，继续使用游标分页。
- 品牌冲突保留本次输入；用户可查看最新内容后明确合并，未编辑字段取另一端，同一字段取本次输入，然后再次保存；也可明确放弃本次修改。参考新增/删除冲突保留输入，用户明确更新列表后重试。
- 未知网络响应重试复用原请求键、参考记录 ID 和条件版本，成功写入不会误报为新的冲突。版本低于已接收响应的收藏结果不回写界面。近期技能去重并保留最近 12 条，通用近期记录最多 100 条；集合和参考总量有上限。
- 写入在租户事务与偏好级锁内完成，只有实际变化才增加 revision。幂等表只缓存操作确认，不额外复制完整偏好正文。

迁移为添加列，不删除旧数据。应用回退可保留该列，但旧应用不提供并发写保证；正式站应优先修复后向前发布，不能把旧代码回退描述为仍有本批保证。外部直接 SQL 写偏好不属于应用写入合同。
