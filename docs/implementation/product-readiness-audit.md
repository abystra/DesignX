# Design X 面向个人用户的产品完成度审计

审计日期：2026-11-18（America/Los_Angeles）。代码和线上版本：`d1843dd3057443d4dfd975307ca9a058cdece544`。线上入口：https://designx.velax.cn。

## 1. 当前判断

当前交付处于“已有可运行工程底座，部分创作流程接通，产品承诺和实际能力尚未统一”的阶段。能够部署和访问、接口测试通过，都不足以说明一个普通用户可以顺畅完成创作。

已经存在真实账户、数据库项目、画板、版本、素材存储和后台导出，应该在这些能力上继续建设。最影响用户体验的是首页突出 AI 创作，但线上 AI 全部关闭；大量技能和工具名称对应通用提示词预设；若干入口虽然能点击，却无法交付名称所承诺的结果；账户生命周期和持续运营能力也未闭合。

本报告保留审计时的现状与证据。后续已选择个人海报首版，整改批次和最新验收状态见 [个人海报实施计划](personal-poster-release.md)。下文的线上观察均指审计基线，不代表后续部署仍然存在全部问题。

## 2. 证据范围

三种证据分别记录，不相互替代。

- **本轮线上实测**：在 aws-1 的独立 Chromium 进程访问正式 HTTPS 域名，使用临时独立账号，真实操作注册、首页、工具目录、视频快捷入口、模板创建与刷新、创作参考复用和 390px 首页。没有拦截或模拟业务接口，没有调用模型。两次诊断运行产生的临时账号、空间、项目和偏好均已清理。
- **本轮源码核查**：沿前端事件 → API → 领域逻辑 → 持久化/Worker 检查实现，定位缺失接口、字段不一致和配置边界。未经实测的问题明确标为源码确认或待验证。
- **此前验收**：前轮部署验证过注册、上传、PNG/PDF 导出及工作区停机后的独立运行；仓库还保存历史本地 AI、API 和浏览器验收记录。这些记录不能直接代表当前线上全部功能。

本轮脱敏结果见 [线上核查证据](product-readiness-evidence-2026-11-18.json)。未重跑全部自动化、真实模型质量测试、多人压测、支付测试或生产备份恢复。

## 4. 具体问题与修复验收

优先级按交付门槛定义。P0 为向普通用户开放前要消除的断路和错误承诺；P1 为核心产品完整性；P2 为规模化和按商业模式选择的扩展。下文保留原始待办定义；完成状态以后续实施计划及验收记录为准。

### F01 · P0 · 首页承诺与线上能力不一致【线上复现】

`App.jsx:300` 的首页主文案承诺 AI 一站创作；`:459` 的 5 个快捷工具全部调用 `openStudio`，不检查能力；`:1426` 的搜索也直接使用静态工具列表。目录页则会禁用不可用项。点击视频快捷入口会创建真实空白项目，且默认进入 Agent 模式。

改造范围：统一首页、目录、搜索、Studio 的能力来源、模式、入口文案和禁用原因。服务未开放时优先提供模板/空白画板等实际可完成的路径；不支持的入口在创建项目之前拦截。无需为每个页面另写一套状态。

验收：关闭 AI 时所有入口一致；不支持的操作不产生新项目；开启某项能力时只开放该项；视频不被误路由到 Agent。覆盖新用户和刷新后入口。

### F02 · P0 · “专业工具”数量远大于已验收能力【源码确认 + 线上观察】

`Catalog.jsx:58–62` 将目录项包装为 `preset`，可用性只取通用 design 开关。`AIStudio.jsx:1341–1344` 将预设名称/说明追加到通用 Agent 提示词。当前专用 Recipe 只有营销海报、商品套图、多尺寸适配。目录中的抠图、试衣、图片翻译、PPT 等没有逐项执行契约和结果验收。

改造范围：每个对外工具定义输入、执行器、输出类型、状态、限制和验收样例；通用提示词归入灵感建议，不承诺专用工具效果。首批只发布真正支持的少量创作场景，目录规模后置。

验收：任何可点击工具都能交付其名称所指的结果。PPT 若没有多页模型和 PPTX 交付，就不能以已可用 PPT 工具发布；普通生成图不能算作背景透明的抠图结果。

### F03 · P0 · 内置素材 → 创作参考 → 新设计报错【线上复现】

复现：资产库 → 创作参考 → 新建参考，使用默认咖啡图片 → 保存 → 预览 → 用于新设计。

`Workspace.jsx:189` 保存 `assetId: 'stock-coffee'`；`:208` 原样传递 `item.assetId`；`App.jsx:844–859` 先创建项目，再向项目关联这个不存在于数据库的素材 ID。后端返回 400 `INVALID_ASSET`，并留下一个已创建项目。源码也存在没有素材 ID 时把参考记录 ID 当素材 ID 的回退。

改造范围：明确 stock、上传素材、参考记录三种身份；内置图片需要持久素材时先摄取为有权限的真实版本；参考记录保存素材 ID/版本 ID，不把记录自身 ID 冒充素材 ID。处理“项目创建成功但素材关联失败”的恢复或补偿。

验收：内置素材、有真实上传素材、无图片提示词三种参考均可复用；失败重试不产生重复空项目；跨账号素材仍拒绝访问。

### F04 · P1 · 品牌保存成功，但 Logo 无法正常传到编辑器【源码确认】

`Workspace.jsx:14,180,218` 保存和选择的是 `logoAssetId`，`Editor.jsx:340–355,2118` 读取和显示的却是 `brand.logo`。颜色与名称保存成功不能证明 Logo 链路也完整。

字体方面，品牌表单提供思源黑体、PingFang、Microsoft YaHei、Georgia；`packages/doc-render/src/render.tsx:51` 实际仅映射到 Noto Sans SC 或 Source Serif 4。需要向用户说明实际可用字体，并让预览和交付一致。

验收：上传 Logo → 设置品牌 → 新设计应用 → 保存重开 → PNG/PDF 均能看见同一 Logo；使用固定素材版本；字体选项与实际渲染相符。

### F05 · P0 · 项目导入承诺 40 MiB，网关只允许 12 MiB【配置确认 + 线上边界复现】

`ProjectImport.jsx:6,224` 和 `apps/api/src/imports.ts:12–19` 支持 40 MiB；`infra/nginx/designx.conf:27` 全站限制 `12m`。本轮对正式域名发送声明 13 MiB 的请求头即得到 413，未上传文件内容或创建任务。

改造范围：为导入路由设置与 multipart 开销相匹配的网关限制，保持普通图片 10 MiB 限制；前端识别网关非 JSON 错误，展示准确原因。

验收：通过正式 HTTPS 域名测试合法 13 MiB、接近 40 MiB 的项目包和超限文件；前两者可导入，超限明确拒绝；普通图片上限保持一致。

### F06 · P0 · Nginx 后面的用户会共用 IP 限流桶【源码/拓扑确认，未做线上压力测试】

`apps/api/src/server.ts:20–23` 配置 `trustProxy:false` 和默认按请求 IP 限流；Nginx 通过回环连接 API。应用看到的是代理地址，登录、注册及全局限流会把不同访客计到同一来源。600 次/分钟的全局额度、12 次/15分钟的注册额度不能按当前部署解释为“每位真实访客”。

改造范围：限定可信回环代理，规范转发来源；认证入口按可信 IP/账号组合限制，已登录业务按用户/空间划分额度。不能简单信任任意客户端的 X-Forwarded-For。

验收：在隔离环境模拟两个来源和两个账号，分别计数；伪造转发头不能绕过限制；随后通过正式代理验证来源解析。不要通过压满线上全局限流来验证。

### F07 · P1 · 账户只能登录，缺少后续管理【源码确认】

认证当前只有注册、登录、me、退出四类路由。头像行为主要是退出或进入项目，缺少个人资料、密码修改/找回、邮箱验证及账户删除路径。未找到相关邮件通道和页面。

本条保留原审计发现。用户后续明确采用普通账号方案：用户名/密码注册登录、个人资料、修改密码与会话管理，不接入邮件、短信或 OAuth。整改状态见 [B2 普通账号](account-release.md)。协议、隐私与素材使用说明应与实际服务及目标市场一致，不以占位按钮交付。

调整后的首版验收：普通账号无需邮箱完成注册登录；旧账号与作品兼容；凭据修改后旧会话按策略失效；账户设置跨设备保存。自助找回、账户删除与数据保留/删除处理单独规划，邮件服务不阻塞首版。

### F08 · P1 · 新手流程主要围绕不可用 AI，真实编辑路径不突出【线上观察 + 源码确认】

可用路径是模板 → Studio → 选中画板 → 精细编辑 → 导出。对只想改一张海报的用户，先进入对话/无限画布增加理解成本。教程 `App.jsx:778` 的“AI 暂未接入”也是固定文案，未来开启后会继续失真。

改造范围：突出“选择模板、上传图片、空白设计”，解释 Board 与精细编辑的关系；以真实能力生成新手引导。内置示例素材、默认品牌和用户上传内容区分来源；头像使用真实用户信息。

验收：全新账号在无需口头指导的情况下完成第一张设计并下载；返回项目能续作；空态和禁用态都给出可执行下一步。390px 覆盖同一旅程，不能只检查无横向溢出。

### F09 · P1 · 模板和素材内容仍由样例文件驱动【源码确认】

`src/data/templates.js` 只有 8 个模板；`library.ts:9–10` 的模板/目录 API 也只是返回文件，前端主入口直接 import 文件。`Artwork` 的 CSS 展示和 `Editor.initialDesign` 的节点构建不是同一份模板文档。静态数据可以用于首版，但需要明确内容版本和一致性。

改造范围：每个模板绑定稳定 ID、版本、真实可编辑文档、由该文档生成的缩略图、适用尺寸及素材来源。首版可使用受控发布文件，不必先建设完整 CMS；后续再补上下架、检索和内容运营。

验收：预览、打开和导出保持一致；模板更新不覆盖用户已创建项目；收藏指向稳定模板；“演示文稿/品牌手册”等标签符合实际单页交付范围。

### F10 · P1 · 创建与搜索入口不一致、易留下重复项目【源码确认】

`App.jsx:842` 的项目创建没有提交幂等键或入口级进行中保护，虽然后端支持幂等。项目搜索 `:1455` 调 `edit(p)`，项目列表调 `openProject(p)`，一个绕过 Board，一个进入 Board。全局搜索也没有统一处理不可用工具和删除后的旧缓存。

验收：双击/断网重试创建同一意图仅有一个项目；从搜索、最近、列表打开同一项目进入一致工作区；已删除项目不会从旧搜索重新尝试编辑。

### F11 · P1/P2 · 项目、素材与任务读取缺少规模边界【源码确认】

## 5. 推荐产品边界与实施顺序

建议第一版服务个人创作者和小商家的单人图片/海报任务，沿用已有架构的单人创作范围。具体付费方案、是否公开注册和首批重点人群仍是产品决策，本次不假定已经确定。

核心交付旅程为：注册/登录 → 模板、空白画板或明确支持的 AI 场景 → 使用自己的素材 → 编辑 → 保存重开 → 导出 → 再次使用。保留项目、素材、版本和任务作为支撑。

| 批次 | 实施范围 | 依赖 | 可交付验收 |
| --- | --- | --- | --- |
| A · 先消除断路 | F01/F02 统一能力入口；F03 参考复用；F04 品牌字段；F05 导入上限；F06 限流；F10 创建和路由一致性 | 当前前后端、Nginx；不需要新供应商 | 现有已开放功能均可完成，所有入口诚实反映可用性；部署正式域名后复测 |

这些批次表示依赖顺序，不是未经估算的交付日期。模板内容、AI配置可以提前准备，功能上线仍按完整旅程验收。

### 每个功能的完成定义

1. 入口可被目标用户发现，名称与结果一致，可用性来自服务端实际支持范围。
2. 有真实输入、接口校验、身份与资源授权、持久化或有明确用途的客户端处理。
3. 等待、成功、空结果、失败、取消和重试都能解释下一步；“成功”必须有可读取的成果。
4. 刷新、退出重登、重新打开仍保留已承诺保存的状态；重复提交不产生重复结果或消耗。
5. 在开发环境验证后，部署已提交版本到 aws-1，再从正式域名验证入口到交付；E2B chisel 只用于开发访问。
6. 记录真实 UI/API/供应商证据及清理情况。静态检查、fixture 通过或接口存在都不能单独作为产品完成依据。

首批建议记录注册完成、项目创建、首次有效编辑、保存成功、导出成功/下载、生成成功/失败及再次打开项目等事件。首次导出率和失败率需要真实数据计算，本次不编造完成百分比或业务指标。
